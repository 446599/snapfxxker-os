# 1902.10: distinct screen package identity

1902.9 rebuilt the screen but kept the 1902.8 package version. The U1 package
manager compares the installed directory name with the configured version;
it does not compare the installed screen binary against the new archive hash.
An upgrade from 1902.8 to 1902.9 therefore retained the prior compiled screen
even though the 1902.9 root filesystem contained the newly compiled archive.

This candidate gives the freshly compiled screen its own package version
`1.2.0-233.20261127.1910` and gives the full firmware the separate version
`2.1.2-233-1902.10`. The ARM64 screen source pin and UI behavior are unchanged.
The 1909 Hub port ordering, identity checks and user-data migration remain in
the provider. The real package-manager `needs_upgrade` path is covered by a
test with an existing 1908 screen installation.

The 1902.9 printer was repaired separately by installing the exact screen
archive already in its firmware. This candidate still requires a complete
cloud build, checksum/readback, upgrade authorization and hardware validation.
