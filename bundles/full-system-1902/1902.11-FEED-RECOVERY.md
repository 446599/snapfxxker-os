# 1902.11 ACE2K lane fault recovery candidate

1902.8 added a target-lane wait before normal feed and retract. When the MCU
reported error mode, the wait rejected the requested operation before the
existing ACE2K driver could handle the MCU's `in_error` refusal. The preceding
1902.7 provider sent the user's motion request to that driver, which logs and
clears that lane's prior error and makes one bounded start retry.

Restore that existing driver path for a target lane in error only when no
host motion, RFID read or native exit owns that lane. Keep connection identity
checks and all ownership guards. Record the MCU's actual fault kind before
handing over; do not interpret the old error as evidence that the physical
route is clear. ACE2K's own motor, stall and jam protection remain active.
Actual movement and the incident's physical cause require real-device checks.

No ACE MCU image is changed or flashed. Screen source and functional features
are unchanged; the distinct screen package version prevents installation from
skipping an updated archive. This package is a candidate pending hardware tests.

For future diagnosis, the host logs raw mode, sequence, motor/filament
odometers and the most recent buffer reading for a blocked or failed tag
movement, and logs unmatched native fault events. This records evidence only:
it does not start, stop, clear, retry or change RFID or motor operation.
Raw status also exposes the real sensor bitmask and the native lane error kind
when the MCU reports error mode, so the existing read-only ACE_RAW_PROBE can
show the actual condition even when the high-level slot presence says ready.
`ACE_RAW_PROBE ACE=<zero-based-unit> SLOT=<zero-based-slot> LAST_EVENT=1`
additionally queries the MCU's retained last host-start terminal event without
starting, stopping or clearing a move; `seq=0` means there is no retained event.
