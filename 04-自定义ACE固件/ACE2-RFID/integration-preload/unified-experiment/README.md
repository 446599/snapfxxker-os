# ACE2 RFID 统一离线实验（2026-11-07 恢复开发）

当前为 **NOFLASH 离线研究版**。正常复位进入自循环，结尾为无效升级标记 `NOFLASH!`，版本标记 `EXUNI!!`。没有设备操作、网络读卡、刷写或硬件验收。

## 当前代码与输入

以交接包的最新统一版本为基线，已在恢复后的环境完整复现：映像 SHA-256 `8c7286fd64e53c561599ddc4dbbd80fa60a4f9414abbb8451e25f6425947231c`。这是修改前的基线，不是当前输出标识。

RF 诊断与队列代码已合入同一个 ARM 映像，共 39 个 hook。存储版本为 EXU1/RDU1：原事件组前缀 32 字节，扩展 608 字节，总请求 640 字节，最小分配块 648 字节；RF/EX/preload/queue 扩展偏移为 16/76/144/184。数据段和 BSS 都为零。队列候选仍只是软件观察，不会授权选卡、槽位成功或进料失败。

来源保持固定：原厂 1.1.31 基底、冻结的 RF 19-hook 输入、accessor c132、RF 诊断 840bafe7 和队列 e568a395。脚本检查这些精确输入，所有历史目录继续作为证据保存。

## 本轮修改

- 每次寄存器访问及操作绑定/重绑定使用 RF owner 的同一到期判断，同时检查普通期限和硬期限，沿用 uint32 回绕规则。
- SPI 状态读取前后检查实际操作身份和到期状态；观察到到期或身份变更后，停止后续 DR 写入，保留调用方输出和隔离状态，不补充预算或释放未知所有者。
- 新增 180 条到期回归断言，覆盖边界、回绕、每个 SR 读取点、卡住的 SR、嵌套中断屏蔽、输出发布和重复绑定。修改前实际失败，修改后通过。
- 统一隔离测试在进入真实 RF 重排入口时观察四个槽位的临时队列上下文，然后调用真实拒绝路径并检查上下文清理。
- 验证报告开始即标记 running；异常/中断标记 failed；仅完整成功后记录 passed、源文件/映像/ELF/日志哈希及工具链版本。文件缺失、运行中输入变化或验证后文件改变均不能作为有效 PASS。

## 重现与读取结果

在工程根目录构建一次环境：

```sh
docker build -t ace2-rfid-offline:20261107 -f tools/offline/Dockerfile .
```

执行完整离线回归（容器无网络，未映射设备）：

```sh
docker run --rm --network none -v "$PWD:/work" ace2-rfid-offline:20261107 python3 -u verify_runtime.py
python3 integration-preload/unified-experiment/verification_report.py
```

第二条命令只核对报告状态和列明文件的哈希，不重跑测试。工具链 GCC ARM 14.2.1；`ACE_ARM_BIN` 可指定兼容工具目录。当前映像与 ELF 哈希以 `output/manifest.json` 为准；只有与当前文件匹配且 status=passed 的 `output/runtime-verification.json` 才代表本次完整验证。报告覆盖列明输入，不是任意新建文件的自动整树监控。

测试包含 host C、ASan/UBSan、ARM 编译链接、逐 hook 字节检查和有限 Thumb 指令模型。模拟寄存器/IRQ/时钟与真实硬件不同，不能从断言数量推断实机安全或性能。

## 剩余阻断与下一步

1. 真实 SELECT、后台启动与 AUTH 到槽位失败发布尚未打通；当前 SELECT/worker 拒绝入口、rf_ready=false 和 decoder 发布拒绝继续保留。下一步先确认队列事件到选卡全过程的槽位、代次和任务归属，再实现有界选卡；不能将队列候选直接视为已获得 RF 所有权。
2. 本轮到期修复使用现有离线时钟，未绑定经过验证的 MCU 单调时钟；暂停或停摆的时钟、CPU/MMIO 延迟和任务生命周期仍需单独处理。
3. HALT 或传输超时后可能无法完成寄存器清理；尚无独立清理预算、可靠恢复或电气关闭 RF 的证明。
4. 共享缓存一致性、全部 GPIO/中断写入路径、堆栈余量、电机/热控停止及掉电/SWD 恢复没有硬件验收。
5. 七个生产证明符号仍未绑定；生产链接必须失败。禁止通过清除复位自环、改升级尾标或填入假证明将实验输出转成可刷文件。

本轮独立代码审查认可到期修复的源代码逻辑，完整测试结果另见报告；不据此声明真实读卡或物理停止已经可用。
