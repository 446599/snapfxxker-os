# RF runtime experiment: DO NOT FLASH

This independent copy starts from accessor-experiment c132f10a9a91f4bf7a5a5917772a61ea123e74d4d7a8e9b7fb8cb65161a89750. It is an actual linked stock-prefix ARM image, not merely a state-machine model, but it is deliberately non-operational and is not release firmware. The frozen RF 19-hook snapshot and c132 preload snapshot are unchanged. `BASELINE-README.md` is historical, not this revision's result.

## Reproduce

From this directory, run `python3 verify_runtime.py`. It uses the already present GNU ARM toolchain, exact stock input and parent build helpers; no installation, network, device or updater is used. `build_accessor.py` without `--offline` refuses. Production linking is intentionally rejected for five missing proof bindings; only the explicit offline link permits their inert sentinel references. No whitelist or updater version file is generated.

Outputs: `output/ACCESSOR-NOFLASH.offline-image`, `build/ACCESSOR-NOFLASH.elf`, `build/combined.dis`, `build/symbols.json`, `output/manifest.json`, `output/runtime-verification.json`. The final manifest is authoritative for hashes. `.su` files contain compiler local frame sizes, not whole-stack proofs.

## Actual changes

- F574/F5D0 stock byte/void accesses remain redirected to checked SPI transport. Every register exchange checks a live exact operation, reader, boot/generation/sequence and STOP epoch. A single budget spans the operation; no retry replenishes it.
- The task identity is the exact stock current-TCB pointer at 0x20001DD0. PendSV 0x08009060 / 0x08009068 and scheduler 0x08013F14 / 0x08013F98 prove this mapping. Direct MRS IPSR rejects interrupt context, zero/misaligned TCB is rejected, and an exchange busy bit blocks same-task recursive use. The final validity check, busy release and byte publication share one metadata critical section. No SPI polling is performed with IRQs disabled. This does not prove task lifetime, TCB-reuse handling, every indirect stock writer, or physical STOP.
- E108 now branches to `br_stock_halt`, retaining the stock entry/tail-return ABI. It sends the exact 50 00 request using command 4, no Transceive StartSend, shared finite poll budget and required TxIRQ. Timer-only, Idle-only, receive indication, errors, budget expiry and cancellation are failures. Normal-path digital cleanup checks Idle/Crypto1/FIFO/IRQ and restores nine saved configuration registers. BR_OK means these register observations only, not tag HALT acknowledgement, RF quiescence or safe release. The original F32C return PC E187 is also recognized defensively only for command4,length2,50 00; output buffers remain untouched.
- The background adapter no longer invents `reader*2` as an owned slot. It rejects because AA78 stores a mutable global lane, AA82 sends only a state byte, and E2B8 later reads the global. The lane has not been carried immutably with the queue event. The separate queue experiment is NOT merged here.
- Actual `decode_native_tag` and `decode_cmd68_uid_tag` call through `decode_bambu_classic` to `br_decoder_probe`, `ar_auth_checked`, and four `ar_read_checked` operations. Raw SELECT return and actual selected UID/BCC bytes are retained. The old void/byte AUTH and its delay loop are removed. A failed byte read cannot become Crypto1 success via 0xff. Typed classifications do not emit AUTH_NEGATIVE. Even coherent AUTH/read observations do not authorize branding, slot success or preload failure; the classic decoder returns failure and the operation is refused. The outer decoder-ready gate also remains false.
- ARM layout is unchanged in size: event prefix32, extension184, payload216, minimum allocation224, allowable blocks224/232/240, RF offset16, EX offset76, preload offset144. EX+0 changes from `initialized` magic to `owner_task`: aligned TCB, bit0 exchange-busy. Independent RF version is magic0x45585231 (EXR1), ready0x52445231 (RDR1). Old v1/v2/queue-v3 versions are rejected. This version must not be blindly combined with a separately expanded queue tail.

## Checked scope

Host compilation and ASan/UBSan run actual integration C with explicit MMIO/IRQ/allocator doubles, including core, bridge, owner, adapter, storage, preload accessor, HALT and typed decoder probe. Tests cover SPI faults/STOP at every poll, budget cutoffs, all ISR numbers1..255, task changes, same-task reentry, final-publication IRQ unmask, stale operation identity, invalid HALT caller/length/payload, frozen IRQ, reader errors, wrong readback, missing state, fallback32, size/overflow/version and ready-last cases. The owner suite runs a 100000-event state test. Counts overlap between some suites and must not be summed as unique checks.

The combined image has 29 actual branch hooks. Verification reconstructs the entire changed stock prefix, verifies every branch target and ABI patch form, checks two reproducible ARM links, BSS/data=0 and text within the documented application region. A limited Thumb instruction model tests 4380 preload branch cases; it is not an ARM CPU emulator or actual RTOS execution.

## Still blocked, exact paths

1. Real startup is not exclusive/proven: EA14 is a perpetual task, DD5A changes SPI/GPIO configuration, and EA38/EA40/EA56/EA5E write GPIO outside E244. Worker entry remains rejected. All writers and ISR/computed aliases are not closed.
2. SELECT DEB6 still rejects before its 13C70 scheduler delays/assertion loop. E244's E4DC retry loop can repeat indefinitely with a frozen tick and successful SELECT. E244 E4B6 and CMD68 E7FE delays are not cycle-bounded. CMD68's direct GPIO E7FA and decoder `ensure_reader_power` also lack a proven electrical/bounded startup contract.
3. E70C/E74C (CMD14) combine GPIO changes with queue16630 timeout0xffffffff. Do not retain those while holding owner. CMD13 E910 only needs coherent cache reads, not fabricated RF transactions. Cache publication/invalidations still require a complete coherent protocol.
4. The ordinary finite poll quota bounds source-level iterations, not CPU bus stalls, wall-clock latency or lease duration. `rf_platform_now` is still offline fixture time; expiry is not a real clock contract. Stock TASK/heap/TCB lifetime, boot identity, ABA/free/reuse remain unproved.
5. On HALT budget/transport/cancel failure, early return plus quarantine can prevent register cleanup entirely. There is no reserved cleanup budget, verified recovery or safe forced release. Timer stop-now behavior is not established, so TimerIRQ may reappear during/after readback. TxControl is restored, not forced antenna-off. Required data: exact reader/clone register specification and board GPIO/power wiring; approved hardware traces of SPI/CS/aux, timer completion and failed-transfer recovery. None was accessed here.
6. Polls recheck STOP/quarantine after SR reads, preventing the observed injected cancellation from authorizing another DR write. An interrupt after the check can still race an in-flight byte. This is not immediate physical STOP or an atomic STOP/MMIO contract.
7. Typed AUTH still lacks a fresh owned SELECT capability, terminal-state verification on the real silicon, and end-to-end cleanup/identity authorization. It cannot feed an owned preload failure. Neither wrong key nor Bambu identity is inferred from accepted hardware status.
8. No positive heap or stack headroom has been proved. Heap geometry is 22512 bytes, but actual peak use/lifetime is unknown. Payload216 costs at least184 bytes more than stock payload32 (minimum blocks224 vs40). Local compiler frames include HALT48, typed AUTH112, typed READ104, decoder probe112, native decoder184 and classic helper120 bytes; these are not additive worst-case whole-task/IRQ stack measurements.
9. Physical motor/heater STOP and thermal behavior remain unproved. `rf_platform_ready` is false, quiescence returns RF_UNVERIFIED, cleanup refuses success, and decoder publication is denied. Five preload production bindings remain unresolved in the production link.

## Permanent barriers and limitations

Normal reset vector and old reset entry lead to a fixed e7fe self-loop; there is no option to enable boot. Exceptions retain stock vectors, IRQ/NMI behavior is not contained, and no physical fail-stop is claimed. The trailer is invalid `NOFLASH!` and the visible version is `EXRF1!!`. No device test, CPU/RTOS emulation, thermal test, electrical test, firmware install or flashing was performed. Do not flash this image.
