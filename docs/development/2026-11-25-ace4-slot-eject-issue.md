# ACE4 二槽、三槽退料问题（2026-11-25）

## 现象

U1 上 ACE4（设备索引 3）在线，打印机空闲。部署 MultiACE provider `1.27b-233.20261122-flow.15.116` 后，尝试从 ACE4 二槽退料：

```text
ACE_SLOT_EXIT ACE=3 SLOT=1
```

Klipper 接受了命令，但动作状态返回：

```text
slot_action: state=error, kind=eject, ace=3, slot=1
message: discover_device 响应帧无效
```

二槽仍显示 `ready`，未见退料完成。三槽（`SLOT=2`）尚未测试，当前仍显示 `position_unconfirmed=true`。

## 同时观察到的状态

- 打印机：`standby`；喷头、热床目标温度均为 0。
- ACE4：已连接，协议 `ace2k`，状态 `ready`。
- ACE4 第四槽仍连接着喷头 4；不得把该槽当作本次退料目标。
- ACE4 二槽对应喷头 2，三槽对应喷头 3；这两只喷头当时均未检测到耗材，来源记录为空。
- 失败信息指向 `discover_device` 响应帧格式/解析，不是机器拒绝开始、喷头占用或“未停稳”保护。

## 当前结论与待办

`.15.116` 中加入的 ACE2K 身份刷新没有解决此机的实际退料问题：二槽请求仍因 `discover_device` 响应帧无效而结束。现有证据不足以判断响应帧是设备发出的异常数据、串口收帧问题，还是 MultiACE 解码/校验不兼容；需要后续结合 ACE4 的原始串口帧和协议解析路径定位。不要绕过设备身份校验，也不要在未确认二槽动作结束前尝试三槽。问题修复后应分别验证二槽与三槽；本记录本身不代表已修复或验证通过。
