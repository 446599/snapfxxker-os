# 给后续 AI 的交接提示

你接手的是 snapfxxker-os，目标设备为 Snapmaker U1 与 ACE 2 Pro。用户当前的主要问题是**报错过多、进退料卡住、需要重启、版本和文件混乱**。优先恢复稳定、简单、可继续操作的体验。

## 一、先使用正确的源码

先读 `components.json` 和根 `README.md`，按四层工作：

| 层 | 目录 | 只能负责什么 |
| --- | --- | --- |
| 原厂固件 | `firmware/stock/` | 官方镜像、固定版本、校验与原厂行为参考 |
| 屏幕显示包 | `packages/screen/` | 显示、字体、用户操作与状态展示 |
| multiACE 主机包 | `packages/multiace/runtime/` | 主机侧通信、进退料、RFID、余量、恢复与 Web |
| ACE 自定义固件 | `firmware/ace/` | ACE 内部 MCU 镜像、补丁和刷写协议相关资料 |

`providers/multiACE` 是上游参考和早期候选；`deliverables/` 是历史交付快照。不要同时改三套 `ace.py`，也不要把旧 provider 整包覆盖进当前运行源码。当前 multiACE 从完整 Flow.13 加已推送的 Flow.15 修复演进，版本读取 `packages/multiace/runtime/VERSION`。

`build-233.sh` 与 `233-firmware.json` 用于复现旧 UI.8/single.5 整包；它们不是当前四组件构建的隐含入口。新的独立入口是 `python build.py <组件>`。

## 二、不要用防御性编程掩盖问题

**不要因为“怕出问题”就增加一个保护层。** 先复现故障，检查实际调用链，并比较原厂已有的实现。能修正条件、补齐收尾或删除错误判断，就不要再写 guard/supervisor/manager/fallback。

具体约束：

1. 原厂已实现的状态切换、运动/加热保护、命令错误与暂停机制直接复用。一个操作只由一个状态机负责，屏幕与 Web 负责显示和下发操作，不重新推测电机状态。
2. 无标签、未知余量、短暂等待、用户取消不等于硬件故障。优先显示状态或可重试提示，不触发 Klipper 内部错误 shutdown。
3. 普通失败必须经过已有清理路径退出：结束当前动作、释放 busy/队列占用，保留真实料路和喷头状态，允许用户重试或取消。不要要求重启来清一个软件状态。
4. 不增加无上限重试、每层独立超时、跨模块重复锁、永久故障锁存、重复确认弹窗或无来源的新配置项。已有有限恢复足够时不再加第二套。
5. 不用 `except Exception: pass` 隐藏故障；不把可预期的普通 `RuntimeError` 泄漏到 Klipper 命令分发器。命令拒绝用现有 `gcmd.error`，任务结果用现有结果字段。
6. 保留必要的物理边界：加热保护、确认的共用料路占用、无法确认电机停止。不能为了少报错伪造成功、清空未知料路、删除 STOP 校验或在停止失败后继续运动。
7. 报错信息面向操作：说明当前发生什么、能否重试、应做什么。日志可以保留技术细节，用户界面不要重复弹同一原因。
8. 新增检查前写清楚它针对哪条真实故障；找不到实际触发路径和合理收尾，就先不要加。

## 三、本轮已经修复，避免改回去

- `AUTO_MODE` 开关不清除 `LOAD_FINISH`，与原厂一致。
- `FEED_AUTO UNLOAD=1` 未传 STAGE 时也会完成机器状态收尾；`prepare` 则继续等待后续阶段。
- 已经成功装载且喷头传感器确认有料时，重复 LOAD 不动电机，也不要求老来源补全额外元数据。
- 普通来源预检拒绝是标准命令错误，避免上升为 Klipper 内部错误关停。
- hot-seat 压料阶段的 STOP 未确认不能被外层捕获后继续挤出。
- 正常 Anycubic/OpenSpool NTAG 可以读取；只读一遍数据，复用已有 UID 与回停确认后提交逻辑。
- 普通未识别结果是 pending 信息，余量未知不自动改成失败；回停或 STOP 未确认仍是真实错误。
- vendored provider 不再按旧 Git 子模块 SHA 验证；安装依赖导入用 `python -B`，不新建 root 私有字节码目录。

原厂依据固定为 `Snapmaker/u1-klipper@7ac453b50fe6779b2ec0b759038a17da5e6d671d` 的 `klippy/extras/filament_feed.py` 与 `klippy/gcode.py`。这是真正的官方源码行为参考，不是把第三方项目称为原厂。

## 四、验证和交付要求

只为实际回归风险写行为测试，优先运行真实入口。不要复制实现写一个必过测试，不要因为测试越多越安心而无限扩张范围。

交付时清楚区分：

- **源码已提交**：远端分支与提交号可回读。
- **包已构建**：给出组件、类型、版本、SHA-256；代码更新包不能称完整应用或整机固件。
- **设备已安装**：必须来自本次真实设备操作证据。
- **实机已验证**：列出实际验证动作；离线回归不能当成连续换料成功。

原厂镜像与 ACE 基础镜像缺失时如实说明，不拿别的版本补位，不生成假固件。屏幕源码包不等于 ARM 可执行包。分层之后仍需要现有 233/PAXX 安装桥接，不能宣称原厂裸系统已一键支持所有模块。

用户已经授权的可逆修复、验证和仓库提交直接完成，不重复问许可。遇到阻塞先完成可做的工作，只有真正缺输入或权限时说明具体缺口。用户的最新明确要求优先于本交接。
