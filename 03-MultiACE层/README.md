# 03 MultiACE 层

这一层在 **U1 打印机端**运行，负责向 ACE 发送指令、跟踪耗材位置、进退料、换料和烘干。不在 ACE 料盒 MCU 上运行。

- [MultiACE 源码](multiACE/)：由 `233-firmware` 直接跟踪，不再是独立子模块。维护分支 `codex/233-firmware`，整理时提交 `3c44e71e190d0e38c9e513c515aa1261f182f3b6`。
- [Klipper 主实现](multiACE/multiace/klipper/extras/ace.py)、[ACE 配置](multiACE/multiace/config/extended/ace.cfg)、[测试](multiACE/tests/)。
- [11 月 22 日边烘边打差量](print-drying-20261122.patch)：针对当时的现场基线，不是上述分支的完整运行包。完整现场记录在本地 `verification/print-drying-deploy-20261122/`。
- [喷头有料时退料差量](loaded-head-unload-20261122.patch)：基于现场包 `1.27b-233.20261122-flow.15.73`，在解包根目录应用；补丁中的 `tests/` 来自该现场快照，若仅更新运行文件，可用 `git apply --include='klipper/extras/*'`。仅取消旧位置记录对原槽喷头退料的拦截，不改变进料或整根退出 ACE 的规则。
- [喷头有料时忽略过期位置会话记录](loaded-head-unload-session-guard-20261123.patch)：在上述差量应用后继续应用。喷头传感器明确有料、原料源记录存在且当前 ACE 身份和喷头到槽位映射吻合时，不再要求旧加载标记、进程会话或插槽计数匹配；真实设备身份变化、路线冲突、喷头无料、料槽忙碌或停机故障仍会拦截。
- [原槽退料不被助力旧错拦截](ignore-unload-assist-error-20261123.patch)：基于现场 `.15.75`。仅在停止并核对原槽后，让 `assist_error` 不拦截本次有限回抽；回抽结束仍检查槽位及喷头。正常打印、进料和其他错误不变。
- [退料助力保护交接](unload-assist-handoff-20261123.patch)：基于 `.15.75` 构建 `.15.77`。只在确认为原槽且已收到停止回复时，暂不依据 `assist_error` 或缺失的 CMD76 卡死回抽；保留槽口和动作完成反馈。
- [喷头清空后退出原槽](stopped-assist-empty-head-eject-20261123.patch)：基于 `.15.77` 构建 `.15.78`。喷头明确为空、原槽停止且仍有料时允许正式退出原槽，运动开始后仍检测故障。

- [普通 V2 进料按喷头到料停止](bounded-head-load-20261123.patch)。在现场包 `.15.83` 上应用，生成 `.15.84`。每次按原槽的设定长度送料，喷头开关检测到料就停。测量轮读数偏低或缺失时只记日志。普通进料送完仍未到喷头时，按该喷头设定的次数在原槽短退后重试。
- [退料后直接退回原槽](one-way-unload-20261123.patch)。在 `.15.84` 上应用，生成 `.15.85`。普通退料已确认喷头清空、原槽已有停泊距离时，省去把料送回喷头找开关的动作。缺少本次实测距离时，扣除前面各段短退，只向后走剩余长度。收尾确认喷头无料、槽口有料，保留原有停泊距离记录。
- 在 `.15.85` 上应用 [首尾采样对照测试补丁](endpoint-feed-20261123.patch) 可生成 `.15.86`。
- 在 `.15.86` 上应用 [日常换料首尾采样补丁](endpoint-swap-20261123.patch) 可生成 `.15.87`。普通进料通过喷头开关确认到料，退料使用同一路料的停止状态、喷头和槽口信号。打印中由 ACE 报告料仓故障。
- 在 `.15.87` 上应用 [连续退料补丁](continuous-unload-20261123.patch) 可生成 `.15.88`。已知停放距离的普通换料会一次回卷到停放位置。从已装料的喷头点「退出 ACE」会持续回卷到原槽口退空。
- 在 `.15.88` 上应用 [喷头提前退空时连续退出的补丁](continuous-exit-20261123.patch) 可生成 `.15.89`。喷头在热端准备期间已经松料时，同一次「退出 ACE」也会直接回卷至槽口退空。

在 `.15.89` 上应用[同槽拔插后自动识别料路的补丁](reinsert-source-20261123.patch)可生成 `.15.90`。同一台 ACE 的同一槽重新检测到耗材后会沿用原料路。暂停时也会更新，送料失败信息会保留。

在 `.15.90` 上应用[打印换料的退料与续打修复](swap-recovery-20261123.patch)可生成 `.15.91`。打印中退料报错时，恢复流程使用本次换料开始的位置和喷头。连续退料为启动留出时间，仍检查喷头是否退空、料仓状态和总时限。

在 `.15.91` 上应用[换料短退自动重试补丁](short-unload-recovery-20261123.patch)可生成 `.15.92`。换料时若喷头已经退空，ACE 一次退到位。若喷头仍有料，先发有限长度的短退；短退完成后仍有料时，由原版热端退料流程重新松料。后续只退剩余的指令长度，重试次数沿用 `unload_retry`。

在 `233-firmware` 运行专项测试，使用已安装 `pyserial` 的 Python：

```sh
python -B providers/multiACE/tests/print_drying_selfcheck.py
```

233 整包构建可能使用 [固定的离线包](../01-原厂固件/233-系统集成/bundles/233-dev.2/manifest.json)。改了 provider 后，要核对实际打包来源，不能假设修改自动进入镜像。
