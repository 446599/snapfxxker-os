# MultiACE Flow15：缓冲助送料与可恢复进退料

版本：`1.27b-233.20261117-flow.15`。本目录在原 Flow14 源码包上继续修改，基线是
`446599/snapfxxker-os@adb1dda5935c227ab1ba40d5bd842763ea0921ba` 中的 Flow13。

这是包含 Flow14 变更的**模块更新源码**，依赖已有 Flow13 平台，不是完整 U1 固件，
也不是 ACE MCU 刷机固件。当前完成的是源码、离线行为测试和更新包校验，尚未实机部署。

## 用户可见的变化

| 场景 | Flow15 行为 |
| --- | --- |
| 打印时 ACE 缓冲在等待喷头拉料 | 保留已接受的助送料状态；`ready` 不再触发重复 arm。 |
| 换料、装料接管助送料槽 | 先停本槽，确认实际静止，再发新动作；其他喷头的缓冲不因普通 V2 装料一起关闭。 |
| STOP 回包丢失或停止落入启动窗口 | 立即发送 STOP，并在启动窗口后补一次 STOP；用本次状态和连续编码器样本确认实际停止。 |
| 停止状态暂时未确认 | 空闲/报错时有限自动复核；每个来源事件最多两次实际复核，不自动重启。 |
| 机械 `feed_error` | 保留原错误与来源，确认停止后提示检查；只有明确选择“短退一次”才执行原有有限回退。 |
| 普通 V2 装料成功 | 保存本次已观测耗材距离，不再无条件作废回退记录。 |
| 起点采样较晚 | 保存实际观测跨度的下限，只授权保守回退，不拿机构步数、配置长度补足。 |
| 一次预检忙碌/读状态失败 | 若尚未排入送料命令，恢复原来源记录，避免空操作留下永久失败锁。 |
| RFID 首次识别 | 使用原有 600 mm 最大前伸窗口；归属往返在已扫描窗口内部，累计往返有单独上限。 |
| 识别不到标签或缺少余量标定 | 显示未确认/未知，不把一次未读到标签说成已经转完一圈。 |
| 界面处于打印错误状态 | 仍可停止、自动恢复、重新检查或执行可用的退出动作。 |
| 重连或 USB 枚举变化 | 核对设备 UID、来源和喷头原始到料后再决定助送料；不自动继续打印 G-code。 |
| 来源证据因重启、断线或插拔失效 | 保留原来源，在原槽提供“确认原来源”；核对同一实体 UID、同一旧头/槽与当前传感器后更新连接证据，不允许不同设备接管，也不清空管内占用或装料失败标记。 |

插料计数与本次运行会话一起校验，避免重启后数字碰巧相同而误恢复。正常连续装卸保留
已确认记录，不重复要求确认；连续观察因重启或断线中断时，需要在原槽核对当前料路。
人工确认只修复来源证据，不代替停止复核，也不自动继续打印。

同一 UID 改换 USB 连接路径时，已有停止故障、停车与管内占用记录仍绑定原连接。
本版不会迁移或清除这些记录；如果存在这类记录，界面提示恢复记录中的原连接后复核。
“确认原来源”保存成功不等于已经解锁退出。跨连接路径迁移还需要实机接管与停车验证。

余量标定在现有耗材弹窗的“余量标定 · 高级设置”内。几何、密度和读区校准数据没有编造默认值；
按已归属的耗材料盘 UID 保存，设备 UID/天线对由服务器绑定。保存资料本身不转盘、不送料，
也不立即生成剩余克数；下一次满足证据要求的真实扫描才使用该档案估计余量区间。

## 缓冲的实现边界

当前 ACE2 V2 固件已有 `CMD8 mode2` 助送料闭环，Flow15 管理它的归属与生命周期，
并读取 CMD73 缓冲霍尔状态。每槽 rest/pushed 独立；`pulled_any` 是四槽共享的满缓冲信号，
不能据此猜测某一槽，也不能轮流退所有槽。界面把过期/缺失的缓冲反馈显示为待核。

本版不把 stock V2 伪装成具备 `ace2k buffer_relax` 或 MCU motion-id 回执的固件。
现有连续助送料、喷头到料、ACE 耗材编码器、温度和原厂夹持/冲刷流程继续各司其职。
喷头4前端机械卡料按机主要求保留为硬件问题；本版改进停止、来源保留与恢复操作。

## 测量、停车和换料

`ace_feed_supervisor.py` 观察实际耗材编码器；机构行程用于判断打滑，不替代耗材距离。
只有同一连接/UID/插料代次、本次送料确认、真实头到料与连续静止均成立，才消费一次成功回执。
首次样本确实为零时保存完整观测距离；首段缺失时保存下限。STOP 后最后一段滑行也经过计距校验。
计距不可信不会抹掉已经证实的“停止”，也不会凭空宣布已准确回到原停车点。

历史停车参考不会放大本轮可回退预算，也不会每轮重新扣减250 mm。缺少起点采样时，
仍可能存在较小的回停误差；下限耗尽不代表 Y 后共用管已清空。精确停车及后台并行换料
需要当前实物接管拓扑、标定和热循环证据。本版保留已有共用管互斥约束。

## 离线验证

从仓库根目录运行：

```sh
python3 -m unittest discover -s deliverables/u1-ace/flow15/tests -v
node --check deliverables/u1-ace/flow15/runtime/web/frontend/app.js
```

测试执行实际协议/控制模块以及现有大文件中抽取的真实方法和前端函数。
覆盖 STOP 启动竞态、丢 ACK、迟到帧、取消、UID/插料代次变更、助送料等待、
有限自动恢复、成功计距、回停预算、RFID行程与来源证明、余量输入以及网页操作门槛。
不以历史176项或Flow13历史367项测试代替本次结果；最终结果见 `VALIDATION.json`。

## 可复现构建

```sh
python3 deliverables/u1-ace/flow15/build.py \
  --output /tmp/multiace-module-update-1.27b-233.20261117-flow.15.tar.gz
```

构建器验证每个被替换文件的 Flow13 SHA-256、解析 Python 源码并检查新增同级模块依赖，
生成固定时间戳和排序的归档。新模块要求在基线不存在。原 `source-20261116` 快照保持不变。
源码中 `runtime/` 对应 MultiACE 运行树；`device-service/` 是独立设备服务目录，
不能复制到 Klipper extras。更新必须按托管平台的实际激活路径进行，模块包不能作为整机镜像刷写。

## 实机仍需完成的验收

1. 按实际连接的每台 ACE 验证缓冲休止/拉紧/共享满状态以及已 armed 的 `ready`。
2. 普通装料、普通退料、同喷头换卷各做连续热循环，核对来源、编码器与实际料位。
3. 运动初始阶段取消、模拟丢回复和断线，确认 STOP、迟到命令废弃以及恢复后无旧动作重放。
4. 确认 RFID 回停至允许容差内后才提交 UID，窗口与真实 Y 接头位置兼容；用实测料盘参数/称重校准余量。
